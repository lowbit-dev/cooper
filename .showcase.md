Cooper clears the path for protocol upgrades. You have an HTTP connection. You want to switch to something else — a custom binary protocol, WebSocket, anything that needs a raw pipe. The HTTP/1.1 specification defines a handshake for exactly this: `101 Switching Protocols`. Cooper implements it, on both ends, and returns a `net.Conn`.

That's the whole job.

---

## The problem it solves

Go's `net/http` doesn't expose a clean, composable path to a raw connection. The `http.Hijacker` interface is there, but using it correctly means writing the `101` response by hand, handling the `bufio` read buffer that may already contain the start of your protocol stream, and doing the same on the client side with `http.ReadResponse`. It's not difficult — but it's precise work that every custom protocol implementation would otherwise repeat.

Cooper does it once, correctly, and gets out of the way.

---

## What it looks like

**Server side.** A handler that accepts an upgrade and speaks raw bytes back:

```go
http.Handle("/stream", cooper.Hijack(func(conn net.Conn, proto string) {
    defer conn.Close()
    io.Copy(conn, conn) // echo server
}, cooper.Protocols("myproto/1")))
```

**Client side.** Initiating the same upgrade over an existing connection:

```go
conn, _ := net.Dial("tcp", "host:8080")

req, _ := http.NewRequest("GET", "http://host:8080/stream", nil)
req.Header.Set("Upgrade", "myproto/1")

raw, err := cooper.Upgrade(conn, req)
```

Both sides return a `net.Conn`. What happens next is yours.

---

## Protocol-specific handshake headers

Some protocols exchange additional headers during the `101` handshake. Cooper provides hooks at both ends without learning anything about the protocol itself.

On the server, inject headers into the `101` response:

```go
cooper.ResponseHeaders(func(r *http.Request, proto string) http.Header {
    h := http.Header{}
    h.Set("Sec-WebSocket-Accept", computeAccept(r.Header.Get("Sec-WebSocket-Key")))
    return h
})
```

On the client, validate the server's response before the connection is returned:

```go
cooper.ResponseValidator(func(req *http.Request, resp *http.Response) error {
    if resp.Header.Get("Sec-WebSocket-Accept") != expected {
        return errors.New("accept mismatch")
    }
    return nil
})
```

Cooper runs your validator after its own checks pass. A WebSocket implementation built on top of Cooper needs these two hooks and nothing else from the handshake layer.

---

## What it is not

Cooper does not implement any protocol. It does not frame messages, parse streams, or manage connection state. It does not wrap your connection in anything that changes how it behaves at the byte level. The `net.Conn` you get back reads and writes exactly as the underlying connection does — minus the bytes already consumed by the HTTP handshake, which are prepended transparently so nothing is lost.

The full implementation fits in four small files, none of which require documentation to follow.
